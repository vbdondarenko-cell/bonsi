## Хостинг: що треба знати перед «додаванням на сайт»
- Застосунок — **Next.js 15 із серверним рендерингом** (`/app`, `/admin`, API, серверні дії, PDF). Йому потрібен **Node.js ≥ 20** процес (або Vercel/Docker/VPS).
  Класичний PHP-хостинг із завантаженням файлів по FTP **не запускає** Next.js: завантаження папки `.next` по FTP не є підтримуваним способом.
- Хостинг `uashared43.twinservers.net` (дані FTP отримано від власника): **неможливо підтвердити**, чи є на ньому Node.js (cPanel «Setup Node.js App» / CloudLinux).
  Із середовища розробки FTP недоступний — порт 21 цього хоста заблоковано мережевою політикою (таймаут), тож перевірку, завантаження й розгортання я не виконував.
  Що потрібно від власника: тариф/панель із підтримкою Node.js ≥ 20 або дозвіл розгорнути застосунок на Vercel/VPS, а пошту лишити на хостингу (SMTP працює незалежно від того, де запущено застосунок).
- Пароль FTP було передано в чаті відкритим текстом: **змініть його** після завершення робіт; облікові дані в репозиторій не записувалися.

## Наскрізний тест на production із тестовим клієнтом (після розгортання)
1. Заявка з публічної форми з реальної скриньки → лист «Заявку отримано» в Inbox; запис у `/admin/orders`.
2. Вхід клієнта кодом (лист із кодом через Send Email Hook/SMTP) → «Мої заявки».
3. Адмін: пропозиція → клієнт погоджує → договір (PDF відкривається, текст українською) → рахунок-передоплата (PDF) → «Я сплатив(ла)» → адмін підтверджує → активація.
4. Завдання на Kanban, етап → результат → погодження; запит на зміну → додаткова угода; передача → приймання → завершення; звернення в підтримку.
5. Повтор будь-якої дії подвійним кліком — дубля немає. Чужий клієнт не бачить даних. Видалити тестові дані лише якщо власник дозволить (історію не видаляти).
